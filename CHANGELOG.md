## [Unreleased]

### Added

- **Third-party notices**: `THIRD-PARTY-NOTICES.md` lists every vendored or depended-on third-party artefact (official WMO, OGC, ISO, AIXM and W3C schemas, WMO code lists, `iwxxm.sch`, SchXslt, SaxonCS-HE and its dependencies, test and benchmark packages, the Met Office sample, linked images) with licences, copyright notices, source URLs, how this project complies, and the points still to be confirmed by the maintainer.
- **`docs/RELEASING.md`**: versioning and tag procedure, package contents, the private-phase limitations and the publication checklist for v1.0.0.
- **Element depth limit (AUD-N1)**: `IwxxmParserOptions.MaxElementDepth` (constructor parameter `maxElementDepth`, default 128, must be positive; the root element is depth 1) and the stable error code `XML-DEPTH-LIMIT` (`MalformedInput`, message with the limit and the line and position of the first element over it). The check is a forwarding `XmlReader` (`ElementDepthLimitedReader`) inside the single secure read (`SecureXml`), so it adds no second pass and stops before any `XDocument` is built or validated. It covers every entry point (strings, readers, streams, files, bulletins, SIGWX, GeoJSON export from XML), the built-in XSD and XSLT Schematron validators when called directly with an `IwxxmDocumentContext`, and the optional `Iwxxm.Net.Validation.Saxon` validator (which reads the instance with its own Saxon document builder through the same reader). Real products nest at most about 20 levels; the default leaves a margin of more than six times.
- **Opt-in `net48` test target outside Windows (AUD-M17)**: `IWXXM_TEST_NET48=true` adds `net48` to the core test project on Linux/macOS (reference assemblies from `Microsoft.NETFramework.ReferenceAssemblies`), and the optional Dockerfile stages `net48-compile` and `net48-test` (Mono) compile and run it in a container. The default build is unchanged.
- **Legacy unit alias `kn_i` (AUD-R5)**: the speed readers accept `kn_i` (not UCUM) as `[kn_i]` and always report one aggregated warning per document and field, `ACL-MEASURE-UOM-NON-UCUM-ALIAS` (field, alias, UCUM code, count). The XSD and official Schematron results are unchanged.
- **Real-world SIGWX test data (UK Met Office)**: `tests/Iwxxm.Net.Tests/Samples/external/metoffice/` holds an unmodified 14.2 MB operational WAFS SIGWX bulletin (15 charts, 4252 features) with a README (origin, SHA-256, licence statement and attribution) and a `.gitattributes` that keeps it byte-identical; `ExternalSigwxMetOfficeTests` verify its integrity, the `XML-SIZE-LIMIT` rejection under the default limits, the XSD rejection of the product as published (missing `gml:id`) and, on an in-memory repaired copy, the Schematron, mapping and GeoJSON stages against an independent count of the XML. Findings are documented in `docs/REFERENCE.md` ("Real-world sample: Met Office WAFS SIGWX") and tracked as AUD-R1 to AUD-R5 in `TECHNICAL_DEBT.md`.
- **SECURITY.md (security policy)**: replaces the repository template with the supported-version statement (pre-release: only the latest `main` and the latest published 1.0.0 prerelease), private reporting through GitHub private vulnerability reporting, a modest response target, coordinated disclosure, scope (XML parsing hardening, output injection, supply chain of the embedded official files) and secure-usage guidance. Linked from the README and `docs/README.md`.
- **Dedicated performance benchmarks (AUD-L5)**: `tests/Iwxxm.Net.Benchmarks/PipelineBenchmarks.cs` (BenchmarkDotNet, `[MemoryDiagnoser]`) measures a SIGWX report inside a SWIM bulletin against a standalone parse, the repeated-call and first-call cost of the default validation path with the cached RDF code lists (and the cost of parsing a code list on every call), and a full-suite baseline over the 29 official examples. Indicative container-measured numbers are in `docs/REFERENCE.md` ("Performance notes"); they show no re-serialization and no per-call RDF parse, so no code change was needed. `RuleCacheReuseTests` guards the code-list cache without timing assertions.
- **Security and API test coverage (AUD-M21)**: DOCTYPE, external-entity (XXE) and entity-expansion (billion laughs) payloads are rejected as `XML-MALFORMED` (`MalformedInput`, no file content leaked) on every entry point (string, stream, `TextReader`, file, typed, bulletin, GeoJSON and SIGWX variants); size limits are asserted with the specific `XML-SIZE-LIMIT` code on every entry point, including non-seekable streams and text whose UTF-8 form exceeds the limit; every public facade member is exercised.
- **Translation metadata (AUD-U8)**: `IwxxmReport.Translation` (`TranslationMetadata`: `TranslatedBulletinId`, `TranslatedBulletinReceptionTimeUtc`, `TranslationCentreDesignator`, `TranslationCentreName`, `TranslationTimeUtc`) exposes the `common.xsd` translation attributes of every report, including reports inside a bulletin; `null` when the report carries none (the official `WAFSSignificantWeatherForecast` type does not declare them). Times are normalised to UTC; an unparseable time is a mapping error (`ACL-TIME-INVALID`). `TranslationFailedTac` is unchanged.

### Changed

- **Packages include the notices**: both NuGet packages now carry `THIRD-PARTY-NOTICES.md` at the package root (next to `LICENSE`), and the Dockerfile pack stage fails the build if either package lacks it, `LICENSE`, or (Saxon package) `licenses/SchXslt/LICENSE`.
- **`SECURITY.md` reports in two phases**: until v1.0.0 (private repository) vulnerabilities are reported directly to the maintainer through the private channel that granted access; from v1.0.0 GitHub private vulnerability reporting is used (to be enabled at publication).
- **Met Office sample licence wording**: the sample README records that the package carried no licence file, the maintainer's confirmation (2026-11-05) that the data is redistributable, and the attribution to the UK Met Office.
- **Default size limit is 50 MiB**: `IwxxmParserOptions.MaxDocumentBytes` defaults to 52,428,800 bytes (was 10 MiB) and `MaxCharactersInDocument` to 52,428,800 characters (was 10,485,760; the same number, so a document within the byte limit never exceeds the character quota in UTF-8 or UTF-16). Large operational products such as the 14.2 MB Met Office WAFS SIGWX bulletin no longer need raised limits. `XML-SIZE-LIMIT` is tested at the new boundary. Memory cost at the cap (indicative) is recorded in `SECURITY.md`; the element-depth limit (AUD-N1) is described under Added.
- **SIGWX validity may be an instant (AUD-R2)**: a WAFS chart whose `gml:TimePeriod` has `beginPosition == endPosition` (as the Met Office publishes them) is valid; `DOMAIN-SIGWX-VALID-PERIOD` now only reports an end before the start. Forecast groups of aerodrome reports accept an instant as well; SIGMET, AIRMET and TAF validity periods stay strictly ordered.
- **Tropopause contour model (AUD-R3, breaking, no consumers yet)**: `Tropopause` has the new `ContourLevel`; a WAFS contour no longer produces one `TropopauseSpotHeight` per ring vertex (including the repeated closing vertex), `SpotHeights` holds only genuine point spot heights, and `Tropopause.Create` takes the contour level (`DOMAIN-TROPOPAUSE-CONTOUR-LEVEL`). GeoJSON: the `TROPOPAUSE_CONTOUR` polygon carries `level`, `levelUom`, `levelReference`, ...; `TROPOPAUSE_SPOT_HEIGHT` points are exported only for point features (the Met Office bulletin: 6,102 features instead of 16,717). Golden masters changed: the `WAFS-Example` domain and GeoJSON files (spot heights removed, level on the contour) and the domain dump of `sigwx-swh-2025-2` (`ContourLevel = null`).
- **Global bounding box (AUD-R4)**: the collection `bbox` is a wrapping box (`west > east`) only when the smallest arc containing every position is at most 180 degrees wide; features spread over the whole longitude range get the plain extent (for example `-180` to `180`) instead of a near-empty wrapping box.
- **Stream error codes unified**: the SIGWX stream entry point reported `XML-EMPTY-STREAM` / `STREAM-NOT-READABLE` while the general entry point reported `STREAM-EMPTY` / `STREAM-UNREADABLE` for the same conditions. Both now report `STREAM-EMPTY` and `STREAM-UNREADABLE` (renamed: `XML-EMPTY-STREAM` -> `STREAM-EMPTY`, `STREAM-NOT-READABLE` -> `STREAM-UNREADABLE`).
- **Error-code documentation is complete and tested**: `docs/REFERENCE.md` lists every stable code emitted by the library, grouped, with meaning, typical cause and remediation, and `ErrorCodeDocumentationTests` fails when the source and the tables diverge. Duplicated code literals (`ACL-JS-CORE-FL`, `ACL-CIRCLE-RADIUS-MISSING`, `ACL-GEOMETRY-SEGMENT-UNSUPPORTED`, `DOMAIN-VERTICAL-LIMIT-INVALID`, `MAPPER-ERROR`, `GEOJSON-EXPORT-ERROR`, `XML-EMPTY-STRING`, `XML-SIZE-LIMIT`) are defined once; no other code was renamed.
- **Documented intentional copies**: `RetryOnFailureLazy` and `BoundedOutputStream` exist in the core and in the Saxon package on purpose (zero-dependency core, no public API); each copy now says so and names the other.
- **Documentation overhaul**: new [Getting started guide](docs/GUIDE.md) (pipeline and layer diagrams, `Result<T>`, document types and visitor, validation levels, security limits, GeoJSON, value-object cookbook, and worked examples for SIGWX jet streams and clouds, METAR/TAF and SIGMET), [reference](docs/REFERENCE.md) (one example per product family, ports, full error-code table, value objects, namespaces) and [documentation index](docs/README.md), with hand-drawn SVG illustrations under `docs/assets/`. The README is now a concise landing page that links to them; its long usage sections moved to the reference with every snippet compiled against the packaged library. CONTRIBUTING gains a "Documentation" section describing how the snippets are verified. No library code changed.
- **Documentation (AUD-C3 remainder)**: README and TECHNICAL_DEBT state that the core default business-rule validation is the built-in XSLT 1.0 subset (11 of 165 official rule IDs plus code-list checks) and that the complete official rules require `UseOfficialSchematron()` (`Iwxxm.Net.Validation.Saxon`).
- **CI least privilege and tag-based versioning (AUD-M19)**: the workflow (`.github/workflows/ci-cd.yml`) has workflow-wide `permissions: contents: read`, grants `packages: write` only to the publish job, publishes only for version tags `v*` instead of every push to `main`, derives the package version from the tag without any build-time dependency (other builds produce never-published `-ci.<run>.<attempt>` prereleases), no longer hides version collisions with `--skip-duplicate`, and drops the global `DOTNET_ROLL_FORWARD` and the unnecessary `dotnet tool restore`.
- **Build and packaging (AUD-M17, AUD-M18, AUD-L11, AUD-L12, AUD-L14)**: the core test project also targets `net48` when built on Windows (`Condition="'$(OS)' == 'Windows_NT'"`), so the existing Windows CI job exercises `netstandard2.0` on .NET Framework (golden-master comparisons run on .NET only; the tokenizer bit-exactness check allows one ulp on .NET Framework, whose `double.Parse` is not correctly rounded). `global.json` uses `rollForward: latestFeature` and `allowPrerelease: false`; `AnalysisLevel` is pinned to `10.0`; the Docker SDK image is pinned to `sdk:10.0.403` by tag and digest; the Dockerfile copies `nuget.config` before the restore, no longer runs `dotnet tool restore` nor sets `DOTNET_ROLL_FORWARD`, and checks that the symbol package keeps its SourceLink map (`.git` stays in the build context for SourceLink, documented in `.dockerignore`). The redundant `Microsoft.SourceLink.GitHub` package reference was removed (the .NET SDK provides SourceLink); `GeneratePackageOnBuild` was removed. Test and benchmark packages updated: Microsoft.NET.Test.Sdk 18.11.0, xunit 2.9.3, xunit.runner.visualstudio 4.0.1, coverlet.collector 10.1.0, BenchmarkDotNet 0.15.8. `PackageReleaseNotes` points to the CHANGELOG instead of a hard-coded version.
- **Facades hold the pipeline directly (HEX-02)**: `IwxxmParser`, `IwxxmSigwxParser` and `IwxxmGeoJsonExporter` no longer sit in front of inbound ports and use cases; they run the bounded-buffer, schema, business-rule and mapping pipeline themselves over the outbound ports and keep their string, file, typed, GeoJSON and static convenience members.
- **Ports receive a neutral document context (HEX-01, AUD-N3, AUD-L5)**: `ISchemaValidator.Validate`, `ISchematronValidator.Validate`, `IIwxxmDocumentMapper.Map` and `ISigwxDocumentMapper.Map` take an `IwxxmDocumentContext` (public, `Iwxxm.Net.Extensibility`) instead of a `Stream`. The use case owns reading the input: it bounds the size, then has the document parsed once with the hardened reader settings (one place, `Infrastructure/Xml/SecureXml`: DTD prohibited, no resolver, character quotas) and rejects malformed input (`XML-MALFORMED`) before any adapter runs; the built-in XSD validator, mappers and SIGWX deserializer share that single parsed tree (the document is no longer parsed separately by the XSD validator and the mapper), and `IwxxmDocumentContext.OpenRead()` gives adapters that need raw XML (XSLT, Saxon) a read-only stream. A SIGWX report embedded in a bulletin is mapped from its parsed element instead of being re-serialized to a `MemoryStream` and parsed again (bytes are produced only if a custom SIGWX mapper asks for them). `IwxxmDocumentContext(byte[], IwxxmParserOptions?)` lets adapters be called directly.
- **SIGWX code resolution in the Anti-Corruption Layer (DDD-10 remainder)**: `Cloud`, `Turbulence` and `AirframeIcing` no longer keep raw reference strings nor resolve codes in the Domain. `Cloud.Distribution` (`CodeListValue<CloudDistributionCode>?`, replaces `CloudAmount`/`DistributionCode`/`DistributionNumericCode`), `Cloud.CloudType` (`CodeListValue<CloudTypeCode>?`, replaces the raw `CloudType` string, `TypeCode` and `TypeNumericCode`), `Turbulence.Degree` and `AirframeIcing.Degree` (`CodeListValue<...>?`, replace `RawDegreeReference`, the non-nullable `Degree` enum and `DegreeNumericCode`) are translated by `Infrastructure/Mapping/CodeLists` (`BufrCodeTable<TCode>`); the factories take these typed values. The notation is the numeric code of a code URI or the TAC abbreviation of the compact report; an absent reference is `null` instead of `Unknown`. `WmoCodeRegistry` is no longer public (it moved to the ACL). `CodeListValue<TCode>.IsKnown` now compares with the member named `Unknown` (value `-1` for the BUFR enums, whose code `0` is an official code). GeoJSON output is unchanged (references rebuilt by the ACL; a bare numeric code is written as the code URI of its table).
- **Aerodrome model (AUD-M11)**: `RunwayVisualRange.PastTendency` is the enum `RunwayVisualRangeTendency` (was the raw string) and `AerodromeForecastGroup.PrevailingVisibilityOperator` is `RelationalOperator?` (was a string). `Metar.Create` / `Speci.Create` take `AerodromeHorizontalVisibility? visibility` instead of `prevailingVisibilityMeters`, `AerodromeCloud? cloud` instead of `cloudLayers`, and `presentWeatherNilReason`; `AerodromeObservation.PrevailingVisibilityMeters` and `CloudLayers` remain as views of `Visibility` and `Cloud`. The `AerodromeForecastGroup` constructor takes `AerodromeCloud? cloud` instead of the layer list, plus `weatherNilReason` and `temperatures`. New public types: `RelationalOperator`, `RunwayVisualRangeTendency`, `NilReason`, `AerodromeHorizontalVisibility`, `AerodromeCloud`, `AerodromeTemperatureForecast`; `AerodromeCloudLayer` gained `AmountNilReason`, `BaseNilReason` and `NilReason`.
- **Value-object equality (DDD-09)**: `SurfaceWind`, `RunwayVisualRange`, `AerodromeCloudLayer`, `AerodromeForecastGroup`, `EnRoutePhenomenonVolume`, `JetStreamCorePoint`, `VolcanicAshConcentrationCloud`, `TropicalCycloneTrackPoint` and `SpaceWeatherAnalysisRegion` implement structural equality (`IEquatable<T>`, `Equals`/`GetHashCode`, `==`/`!=`): exact comparison of every component, collections compared by content and order, `0.0`/`-0.0` and NaN hashed consistently on every target framework. The existing class value objects (`Cloud`, `JetStream`, `Tropopause`, `TropopauseSpotHeight`, `Volcano`, `Turbulence`, `AirframeIcing`, `TropicalCyclone`, `Sandstorm`, `RadiationIncident`, `GeoPolygon`) gained `==`/`!=` operators that agree with `Equals`. Property-style tests: `ValueObjectEqualityTests`.
- **One public type per file (CLN-03)**: the multi-type files (`AerodromeReports.cs`, `EnRouteHazardReports.cs`, `VolcanicAndSpaceReports.cs`, `WmoCodes.cs`, `VerticalLimit.cs`, `WafsPointPhenomena.cs`, `ReportMetadata.cs`, `ValidationError.cs`, `Speed.cs`, `Length.cs`, `JetStream.cs`, `Tropopause.cs`, plus the internal `DomainInvariants.cs` and `EmbeddedResourceLoader.cs`) were split, one type per file; value objects live in `Domain/ValueObjects`. The only remaining multi-type file is the internal SIGWX transport model `Iwxxm20252.Generated.cs`.
- **`WmoCodeRegistry` (CLN-07)**: the four `Resolve*` methods share one generic algorithm with per-table TAC abbreviation tables; the `>= 0` guard (`Unknown` is the defined member `-1`, never an official code) and the three-digit token limit (largest code of the supported tables is 63; longer tokens are rejected before parsing) are named, documented constants. Behaviour is unchanged.
- **Internal namespace** `Iwxxm.Net.Infrastructure.Mapping.Sigwx` renamed to `...Mapping.Wafs` (it clashed with the new `Sigwx` aggregate name); internal mappers and feature builders follow the new aggregate names (`VaaMapper`, `TcaMapper`, `SpaceWxMapper`, `TcaFeatureBuilder`, `SpaceWxFeatureBuilder`). GeoJSON output is byte-identical.
- **God classes decomposed (CLN-01, CLN-05, CLN-02; AUD-A1 section 8.2)** — internal refactor, no behaviour change:
  - `IwxxmSuiteMapper` (about 1,500 lines) is now a thin composite that loads the document safely and dispatches by root QName through a static registry (`IwxxmReportMapperRegistry`) to one mapper per report family in `Infrastructure/Mapping/Reports` (`MetarSpeciMapper`, `TafMapper`, `SigmetMapper`, `AirmetMapper`, `VonaMapper`, `QvaciMapper`, `VolcanicAshAdvisoryMapper`, `TropicalCycloneAdvisoryMapper`, `SpaceWeatherAdvisoryMapper`, `BulletinMapper`), with shared LINQ to XML readers in `Infrastructure/Mapping/Xml` (GML time and geometry, AIXM features, text and code-list references, mapping error codes, UCUM units).
  - `SigwxMapper` (about 1,000 lines) coordinates `WafsForecastMapper` and `CompactSigwxReportMapper`; each WAFS phenomenon family has its own extractor in `Infrastructure/Mapping/Sigwx` (jet streams, clouds, turbulence, airframe icing, tropopause, point phenomena) plus shared geometry, measure, time and elevated-volume readers.
  - `Rfc7946GeoJsonExporter` (about 1,000 lines) collects features through the new Domain visitor (`GeoJsonFeatureCollector`) and one feature builder per report family (`Infrastructure/GeoJson/Features`), and writes them with a separate `FeatureCollection` writer and JSON writer (`Infrastructure/GeoJson/Writing`). The `switch (report)` type dispatch was removed.
  - **Golden outputs are unchanged**: the canonical Domain model dump and the GeoJSON output (indented with `bbox`, and compact without `bbox`) of the 29 official WMO examples and the two SIGWX samples were recorded as golden files before the refactor and are byte-identical after it.
- **Aggregate invariants (DDD-05, AUD-L10 invariants)**: every aggregate `Create` factory now enforces the same minimal physical/structural invariants and reports **all** violations at once: `ValidUntil > ValidFrom` when both are present (SIGMET, AIRMET, TAF validity and cancelled period, METAR/TAF forecast groups; SIGWX already did), non-empty identifiers (AIRMET now requires the ATS unit designator like SIGMET), defined metadata enums, non-default issue time, zero UTC offset for every `*Utc` value, wind/motion direction within [0, 360] degrees, non-negative speeds, visibility and RVR. Official Schematron business rules are not duplicated.

Unknown elements are ignored, the last occurrence wins for single-valued members, repeated elements are appended, `xsi:nil` on nullable members yields `null`, conversion errors are still reported as `XML-DESERIALIZATION-ERROR`.
- **Architecture tests** are IL-level (`HexagonalArchitectureTests`, NetArchTest.Rules/Mono.Cecil as a test-only dependency) and replace the reflection-signature checks and the `grep` audit in the Dockerfile.

The pack stage builds both packages and fails if `Iwxxm.Net` declares any dependency.

Embedded resource lookups are exact (no suffix matching). Manifest resource names changed to `Iwxxm.Net/Resources/<relative path>`.

- **Inbound ports and use cases (breaking)**: the public interfaces `IIwxxmReportDispatcher`, `IIwxxmSigwxProcessor` and `IGeoJsonExportService` and the internal use cases `DispatchIwxxmReportUseCase`, `ProcessSigwxReportUseCase` and `ExportGeoJsonUseCase` were folded into the facades. Also removed: the `IwxxmParser.Dispatcher`, `IwxxmSigwxParser.Processor` and `IwxxmGeoJsonExporter.Service` properties, and the public facade constructors (`IwxxmParser(IIwxxmReportDispatcher, IGeoJsonExportService)`, `IwxxmSigwxParser(IIwxxmSigwxProcessor)`, `IwxxmGeoJsonExporter(IGeoJsonExportService)`); facades are created only through `IwxxmParserBuilder`. ### Fixed

- **Stack overflow on deeply nested input (AUD-N1)**: a schema-valid `collect:MeteorologicalBulletin` that nests itself (about 25,000 levels, 2.6 MB, far below the size limit; 24,000 levels survived) crashed the host process with an uncatchable `StackOverflowException` inside `XDocument.Validate`; such documents now return an `XML-DEPTH-LIMIT` failure. This also bounds the super-linear time of `XDocument.Load` on deep input (about 4 s at 25,000 levels, 16 s at 50,000, 1.5 to 1.8 minutes at 100,000 and about 12.7 minutes at 200,000), recorded as an AUD-N3-adjacent finding.
- **Windows CI / `net48` test target (AUD-M17)**: the `net48` target of the core test project had never been compiled and failed to build on the Windows job (`System.Text.Json` is not part of .NET Framework). It now references the test-only `System.Text.Json` package for `net48`, the few .NET-only APIs used by the tests (`double.IsNegative`, `ReferenceEqualityComparer`) have portable equivalents, and the tokenizer bit-exactness check no longer breaks on the sign of `-0.0` (which .NET Framework's `double.Parse` drops). The core package is unchanged and still has zero runtime dependencies.
- **No vertex lost in polar caps and multi-lobe rings (AUD-R1)**: a ring that goes around a pole is repeated every 360 degrees, clipped to [-180, 180] and closed along the antimeridian and the pole, so a lobe across the antimeridian keeps every source vertex (three south polar tropopause contours of the Met Office bulletin lost 23 vertices); a ring that crosses the antimeridian more than twice gives separate pieces instead of pieces joined by a zero-width bridge.
- **Bulletin entries are isolated**: an exception thrown by the mapper of one `collect:meteorologicalInformation` entry (for example a custom mapper) becomes a `MAPPER-ERROR` item error of that entry and the remaining entries are still mapped; `OutOfMemoryException` is not swallowed. The warnings of successfully mapped entries are now carried into the bulletin result's `Warnings` (previously only item-error warnings were).
- **Polar caps keep their holes**: a polygon enclosing a pole keeps its interior rings that lie inside the cap as holes of the written polygon. An interior ring that cannot be represented is reported by the new feature property `droppedInteriorRings` instead of being lost silently.
- **No silent geometry loss when reading GML**: an unreadable `gml:interior` ring is a mapping error (`ACL-GML-INTERIOR-RING-UNREADABLE`; rings with too few positions already fail with `GEO-POLYGON-HOLE-DEGENERATE` instead of being skipped). Space weather regions now keep every `gml:PolygonPatch` (`spacewx-A7-3_alternate.xml` and `spacewx-A7-4_alternate.xml` have two; their golden masters now list both areas and the GeoJSON is a `MultiPolygon` with `patchCount`). En-route volumes and ash cloud contours hold a single surface: several patches there are the explicit error `ACL-GML-MULTI-PATCH-UNSUPPORTED` instead of silently using the first one.
- **Portable coordinate rounding**: `GeoCoordinate` and computed GeoJSON positions are quantized to 1e-7 degrees with IEEE 754 arithmetic only (`Math.Floor(|x| * 1e7 + 0.5) / 1e7`, sign restored, negative zero normalized), identical on .NET Framework and .NET Core/.NET. `Math.Round(double, int, MidpointRounding)` differs between runtimes at exact midpoints.
- **Small hardening**: the root-element lookup of the XSD validator reads the shared schema set under the same lock as validation; the byte-stream reader rethrows `OutOfMemoryException` like the text reader instead of reporting `STREAM-READ-ERROR`.

- **Official Schematron locations are real XPaths (AUD-L8 remainder)**: the compiled official `iwxxm.sch` (SchXslt 1.10.1) writes SVRL locations as `/Q{http://icao.int/iwxxm/2025-2}METAR[1]/Q{...}observation[1]/...` (XPath 3.0 braced-URI literals, which `System.Xml.XPath` cannot parse). `OfficialSchematronValidator` now reports `ValidationError.Location` as an absolute, namespace-independent XPath 1.0 that selects the offending element in the instance, e.g. `/*[namespace-uri()='http://icao.int/iwxxm/2025-2' and local-name()='METAR'][1]/*[namespace-uri()='http://icao.int/iwxxm/2025-2' and local-name()='observation'][1]/...` (positional predicates count siblings with the same expanded name; namespace URIs are quoted as XPath literals). The vendored SchXslt files and `iwxxm.sch` are untouched: the steps are rewritten while the SVRL report is read (`Internal/SvrlLocation.cs`). Applications that matched the old `Q{...}` text must switch to the new form (see "Locations of findings" in `docs/REFERENCE.md`).
- **Low-severity fidelity fixes (AUD-L2, AUD-L3, AUD-L8, AUD-L9)**: the joint vertex shared by consecutive curve members/segments of a ring is kept once (previously repeated). Previously unmapped content is now mapped: TC SIGMET `supplementaryAnalysisCollection` (`Sigmet.SupplementaryEvolvingConditions` / `SupplementaryForecastPositions`), VA SIGMET `volcanicAshMovedToFIR` (`Sigmet.VolcanicAshMovedToFirDesignator` / `Name`), TCA observed `movement`, `movementDirection`, `movementSpeed` and `intensityChange` (`TropicalCycloneTrackPoint.Movement`, `MovementDirectionDegrees`, `MovementSpeed`, `IntensityChange`), and WAFS volcano `activityStatus` / `sourceElevation` (`Volcano.ActivityStatus`, `Volcano.SourceElevation`); QVACI `VolcanicAshCloudConcentration`/`ashDensityEqualsOrExceeds` were already mapped and VAA `eruptionDate` does not exist in IWXXM 2025-2. Built-in rule `IWXXM-SIGWX-002` uses the exact 80 kt threshold (41.15552 m/s, previously 41.0 while the message said 41.1) and reports the unit of the compact jet stream; SVRL `location`s of the built-in rules are real XPaths of the context node (`/iwxxm:METAR[1]/iwxxm:observation[1]/...`). GeoJSON numbers are written with the shortest representation that round-trips (`R`, verified, `G17` fallback; previously `G15`), a `null` entry of a string list is written as JSON `null` (previously `NullReferenceException`), U+2028/U+2029 are escaped, and a polygon hole with fewer than 4 positions (after closing) is a mapping error `GEO-POLYGON-HOLE-DEGENERATE` instead of being dropped or written as an invalid ring.
- **Coordinate tokenizer (AUD-L1)**: plain decimal tokens with up to 15 significant digits are parsed as an exact integer significand divided by an exact power of ten (one correctly rounded IEEE operation), bit-identical to `double.Parse` with the invariant culture; tokens with more digits (previously truncated after 15 fraction digits) or exponents use the invariant `double.TryParse` fallback. Only XML whitespace (space, tab, CR, LF) separates tokens (no-break space, U+2028 or vertical tab are no longer accepted as separators). `ParseSinglePoint` rejects extra tokens (`GML-INVALID-POINT`); a 3-D CRS position accepts exactly three. Random round-trip tests compare 300,000 tokens with `double.Parse` bit for bit. Golden files are unchanged (coordinates are quantized to 1e-7 degrees).
- **No silently skipped WAFS features (AUD-L4 remainder)**: a WAFS `iwxxm:feature` given only by reference (not resolved by this version; the official `WAFS-Example.xml` contains one remote reference) is reported as a feature error `ACL-SIGWX-FEATURE-BY-REFERENCE`, and a feature whose phenomenon is outside the supported WAFS catalog as `ACL-SIGWX-PHENOMENON-UNSUPPORTED` (`Sigwx.FeatureErrors` and `Result<T>.Warnings`, partial results), instead of being skipped. Interior rings (holes) of a WAFS tropopause contour are kept in `Tropopause.ContourPolygon`.
- **Warnings no longer fail the parse (AUD-U5, AUD-L8 part)**: only validator findings with `ValidationSeverity.Error` stop the pipeline; warning findings of the schema and business-rule validators (Schematron `role="warning"`/`"warn"`/`"info"`, and every fired `svrl:successful-report` unless its role is `error`/`fatal`) are returned as `Result<T>.Warnings` of the successful result, before the mapper warnings. Previously any finding, including warnings and successful reports, failed the whole parse. A failing stage still reports all of its findings.
- **Declared encoding of string input (AUD-M5)**: `Parse(string)`, `ParseBulletin(string)`, `IwxxmSigwxParser.Parse(string)` and the instance `Process*(string)` members read the string as text (`StringReader`) instead of encoding it to UTF-8 bytes and decoding them with the encoding named by the XML declaration: a string declared `UTF-16` no longer fails and one declared `ISO-8859-1`/`windows-1252` no longer produces mojibake. The use cases re-encode the text as UTF-8 and rewrite the declared encoding to `UTF-8` (a leading BOM character is dropped), so every stage, including custom validators, sees exactly the characters of the string. `IwxxmParserOptions.MaxDocumentBytes` applies to the UTF-8 payload and is enforced while reading.
- **TAC qualifiers and nil-reason semantics (AUD-M11)**: METAR/SPECI/TAF content that was dropped is now mapped: wind speed and gust operators (`SurfaceWind.MeanSpeedOperator`, `GustSpeedOperator`, TAC `P49MPS`), variable wind extremes (`ExtremeClockwiseDirectionDegrees` / `ExtremeCounterClockwiseDirectionDegrees`, TAC `dndndnVdxdxdx`), RVR operator (`RunwayVisualRange.MeanRvrOperator`, `R27/P2000`, `M0050`), minimum visibility with direction (`AerodromeHorizontalVisibility.MinimumMeters` / `MinimumDirectionDegrees`; official `speci-A3-2.xml` 1200 m towards 45 degrees), vertical visibility with its unit and nil reason (`AerodromeCloud.VerticalVisibility`, `VV///` as `notObservable`) and TAF `TX/TN` pairs (`AerodromeForecastGroup.Temperatures`). `@nilReason` is translated against the official register `http://codes.wmo.int/common/nil` (`CodeListValue<NilReason>`), so "no significant weather" (`NSW`, `IsNoSignificantWeather`), "no significant cloud" (`NSC`, `AerodromeCloud.IsNoSignificantCloud`), "no cloud detected" (`NCD`, `IsNoCloudDetected`), present weather `//` (`PresentWeatherNilReason`), clear sky (`SKC` amount with `BaseNilReason` `inapplicable`) and nil layers (`//////`) are distinguishable from content that is simply not reported. An operator or RVR tendency outside the official enumeration is a mapping error (`ACL-OPERATOR-INVALID`, `ACL-RVR-TENDENCY-INVALID`).
- **Bounded business-rule output (AUD-M14, AUD-N3, AUD-L6)**: the SVRL report of both Schematron validators (built-in XSLT 1.0 subset and `Iwxxm.Net.Validation.Saxon`) is written to a size-bounded buffer (`IwxxmParserOptions.MaxRuleReportBytes`, default 4 MB) and streamed back with its own limits instead of the input-document quotas, so a large report is no longer misreported as `XML-MALFORMED`; a runaway report stops the evaluation with `SCHEMATRON-REPORT-SIZE-LIMIT` (`BusinessRuleViolation`). The Saxon adapter no longer keeps the SVRL as a Saxon tree. XSD and Schematron findings are capped at `IwxxmParserOptions.MaxValidationErrors` (default 100) followed by one `XSD-TOO-MANY-ERRORS` / `SCHEMATRON-TOO-MANY-ERRORS` sentinel (an error if any discarded finding was an error, otherwise a warning). Compilation of the XSD schema sets, the XSLT stylesheet and the Saxon engine is cached only on success (`RetryOnFailureLazy`): a failure is reported as a result error (`XSD-SCHEMA-SET-UNAVAILABLE`, `SCHEMATRON-UNAVAILABLE`) and retried on the next validation instead of being cached for the life of the process. The official RDF code lists used by the XSLT `document()` calls are parsed once per process (shared read-only `XPathDocument`s) instead of on every transform, and are no longer subject to the input-document character quota (a small report with a quota just above its size previously failed with `SCHEMATRON-EXECUTION-ERROR`).
- **Local CI never publishes (AUD-H7)**: the Dockerfile `ci` stage only copies the artifacts to `/out`; `tools/run-local-ci.sh` no longer forwards `GITHUB_TOKEN`. A deliberate local publish requires `--publish`, a dedicated `IWXXM_NUGET_PUBLISH_API_KEY`, an explicit `PACKAGE_VERSION` and a clean git tree; `CONTAINER_ENGINE=podman` is supported.
- **METAR/SPECI trend wind (AUD-H4)**: `iwxxm:AerodromeSurfaceWindTrendForecast` is now read, so `AerodromeForecastGroup.SurfaceWind` of a trend is no longer always `null`.
- **Circles (AUD-H1)**: `gml:CircleByCenterPoint` geometries ("WI 250NM OF TC CENTRE" in `sigmet-A6-2-TC.xml`, the TCA CB extent in `tc-advisory-A2-2.xml`, the space weather `DAYSIDE` in `spacewx-A7-3.xml`) are no longer dropped, and a circle in a SIGWX chart no longer fails the chart. A circle whose centre is the placeholder `9999 9999` (official `NIGHTSIDE` example) has no extent and is identified by its location indicator. Curve segments that are not sequences of positions (`gml:Arc`, `gml:Circle`, ...) combined with other segments are reported (`ACL-GEOMETRY-SEGMENT-UNSUPPORTED`) instead of being ignored.
- **Local references (AUD-H2)**: `xlink:href="#id"` is resolved through a per-document `gml:id` index (built once, cached as a document annotation) for times, AIXM features (aerodrome, units, airspaces, runway), SIGMET/AIRMET condition members, VAA ash clouds and space weather groups/regions/locations. The TAF A5-1 base forecast now has its validity, the space weather A7-4 "+6 HR" forecast keeps its regions and QVACI feature times are set. Remote or unknown references stay `null`; reference cycles and self/ancestor references are not followed (chains up to 8 hops).
- **CRS metadata (AUD-M10; requested as "AUD-H10")**: `@srsName`, `@axisLabels` and `@srsDimension` (inherited from the nearest ancestor-or-self, like the official rules) are read: "Lat Long" (default) and "Long Lat" (swapped), 3-D positions (height explicitly ignored), EPSG:4326/4979 and OGC CRS84. Unknown CRSs, axis labels or dimensions are mapping errors (`ACL-CRS-UNSUPPORTED`, `ACL-CRS-AXIS-LABELS-UNSUPPORTED`, `ACL-CRS-DIMENSION-UNSUPPORTED`). The identifier `http://www.opengis.net/def/ers/EPSG/0/4326`, present verbatim in several official WMO examples, is accepted as an alias of EPSG:4326.
- **GeoJSON right-hand rule (AUD-M1)**: exterior rings are written counterclockwise and holes clockwise (signed area on longitude/latitude); the Domain keeps the source vertex order. `sigmet-VA-EGGX.xml` no longer renders as the complement in spherical renderers.
- **Non-finite numbers (AUD-M3)**: `NaN`/`INF`/`Infinity` are rejected at the mapping boundary for every measure, coordinate token and SIGWX transport number (`ACL-MEASURE-VALUE-INVALID`, `GML-INVALID-COORD-NUMBER`); the JSON writer never emits a bare `NaN`/`Infinity` (non-finite property values are written as `null`; a non-finite position is an internal error reported by the facade).
- **Antimeridian (AUD-M2)**: lines and polygons crossing ±180 are split into `MultiLineString`/`MultiPolygon` (RFC 7946 §3.1.9) and the `bbox` uses west > east when the content crosses (§5.2). Rings that go once around the globe (e.g. `spacewx-A7-5.xml` "N80 W180 - ... - N80 W180") are written as polar caps; edges running along the antimeridian between -180 and +180 (latitude bands "W180-E180") are kept as reported.
- **Concurrent validation (AUD-N2)**: validation against the shared compiled `XmlSchemaSet` is serialised per set, because `XmlSchemaSet` documents no instance thread-safety and `XDocument.Validate` writes to the set's `XmlNameTable`. Stress tests cover the official and legacy SIGWX sets, the XSLT validator and the default facade.
- **SIGWX geometry fidelity (AUD-M13)**: curve segments are concatenated in document order whatever their type (the transport model keeps one ordered `gml:segments` list); every `gml:PolygonPatch` of an `ElevatedVolume` is read; interior rings are kept.
- **Per-field unit subsets (AUD-N4)**: units valid in general but not allowed for the field by `iwxxm.sch` are mapping errors naming the field (`ACL-MEASURE-UOM-NOT-ALLOWED`): wind/gust/maximum wind speed `m/s`|`[kn_i]`, speed of motion `km/h`|`[kn_i]`, cloud base/top `m`|`[ft_i]`, AIRMET surface visibility `m` (single-unit fields such as `Cel`, `hPa`, `deg`, visibility/RVR `m` were already enforced).

- **Truthful comments (CLN-06)**: the header of `Infrastructure/Generated/Iwxxm20252.Generated.cs` no longer claims to be `xscgen` output; it states that the SIGWX transport model is hand-maintained. The `GenerateXsdClasses` MSBuild target (`-p:RegenerateXsdClasses=true`), which would have overwritten that file, was removed; `tools/generate-xsd-classes.sh` now only writes a reference scaffold to `artifacts/xscgen-reference/` (README and CONTRIBUTING updated). `GmlCoordinateTokenizer` no longer claims to be zero-allocation: its documentation describes the real allocation profile (result list; one substring per fallback token on `netstandard2.0`), the 1-ulp precision limit of the fast path and its whitespace handling. The `Sigwx` summary no longer claims to enforce invariants "across all 9 phenomena".
- **`JetStream` equality** now also compares `CorePoints` (by content, in order).
- **WMO BUFR code mappings** (`WmoCodeRegistry`, now `Iwxxm.Net.Reports`): every official code of tables 0-20-008, 0-20-012, 0-11-030 and 0-20-041 now resolves to the member that represents its official meaning, and every member value equals the official code. Previously, among others, turbulence code 8 ("Nil") resolved to `LightClearAir`, 19 ("Moderate, occasional severe") to `Extreme`, 20 ("Moderate, frequently severe") to `ExtremeClearAir`, 10/11 ("Moderate"/"Severe", cloud/clear air not specified) to clear-air members; icing code 3 ("Light icing in precipitation") resolved to `Moderate` and codes 10-12 were ignored; cloud distribution codes 13-16 were shifted. Codes of a different table and undefined codes now resolve to `Unknown`. Data-driven tests iterate every concept of the official RDF tables.
- **Units of measure**: `@uom` is no longer ignored. The official SPECI A3-2 example (`<iwxxm:meanWindSpeed uom="[kn_i]">25.0</iwxxm:meanWindSpeed>`) was previously exposed as 25 m/s; it is now `Speed(25, Knots)` (12.8611 m/s). Jet-stream speeds in `km/h` are no longer treated as knots. Single-unit quantities (`Cel`, `hPa`, `deg`, visibility/RVR in `m`, ash density in `mg/m3`) are verified. A missing or unknown unit is reported as a `DomainMapping` error (`ACL-MEASURE-UOM-MISSING`, `ACL-MEASURE-UOM-UNSUPPORTED`, `ACL-MEASURE-UOM-MISMATCH`, `ACL-MEASURE-VALUE-INVALID`); no unit is assumed. `FlightLevel` uses the exact 0.3048 m/ft factor.

- **XSD validation now uses the official schemas**: the previous hand-written XSD subsets (no facets, `MeasureType` as `xs:string`, defaulted `reportStatus`/`permissibleUsage`, missing `recentWeather`/`windShear`/`extension`, non-nillable temperatures) were wrongly described as official. Every standard root is now validated against byte-identical copies of the official WMO IWXXM 2025-2 schemas and their official imports (GML 3.2.1, O&M 2.0, ISO 19139, AIXM 5.1.1, METCE 1.2, OPM 1.2, COLLECT 1.2, XLink/XML), 80 files embedded under `Resources/Xsd/Official/` with path-preserving logical names. Validation goes through `XDocument.Validate` so that schema default attributes (`xlink:type`) do not cause spurious errors in official examples that do not declare the XLink prefix.
- **Code lists**: the single 84-concept `codes.wmo.int-49-2.rdf` was replaced by the 20 official WMO RDF code lists (716 concepts, 690 distinct URIs). Each `codes.wmo.int` `xlink:href` is checked against the official list of its register (with the official IWXXM 2025-2 `owl:versionInfo` filter where the official rules apply it), so valid codes such as `http://codes.wmo.int/306/4678/-SHRA` are accepted. The WAFS BUFR rules now check membership in the official tables instead of a URI prefix.

- **No invented values (DDD-07, AUD-H5)**: the mapper and the aggregate factories no longer replace absent data with plausible values (`DateTimeOffset.MinValue` issue times, `validFrom/validUntil ?? issueTime`, `observationTime ?? issueTime`, `"NORMAL"`/`"OPERATIONAL"`, QVACI density `0.0`, volcano name `"UNKNOWN"`, WAFS cloud/turbulence/icing references `"UNKNOWN"`, tropopause level type `"SPOT"`/`"CONTOUR"`, bulletin issue time `MinValue`, transport-model defaults `reportStatus="NORMAL"`/`permissibleUsage="OPERATIONAL"`, unparseable measures read as `0`, `GND` read as FL000, ATS unit designator replaced by the unit name). Mandatory content (official XSD without `minOccurs="0"` / `use="required"`) that is absent is a `DomainMapping` error; optional or nil content, and mandatory properties given only by an `xlink:href` reference (not resolved by this version), map to `null`. Unparseable time positions are reported (`ACL-TIME-INVALID`) instead of being silently dropped.
- **Vertical limits (DDD-08, AUD-M7, AUD-U7)**: "15 km AMSL" is no longer FL492 and "SFC/3000FT" is no longer FL030; limits keep the reported value, unit, vertical reference (`aixm:upperLimitReference`, `iwxxm:*VerticalReference`), special value (`GND`, `UNL`, `FLOOR`, `CEILING`) and nil reason. Official VONA A7-1 (ash at `15000 M MSL`) and WAFS (metres MSL) values are kept as reported.
- **Equality contracts (DDD-06, AUD-M6)**: `GeoCoordinate` quantizes latitude/longitude once at construction to 7 decimals (`GeoCoordinate.Precision`) and compares exactly, so `Equals` and `GetHashCode` agree and equality is transitive (10.00000004 and 10.00000006 are now different values with consistent hashes); `GeoPolygon` compares and hashes the contents of its interior rings.
- **Exceptions no longer escape `Result<T>` (CLN-04, AUD-M4)**: file-based members (`ProcessFile*`, `ParseFile*`, bulletin, SIGWX and GeoJSON variants) report `FILE-NOT-FOUND`, `ACCESS-DENIED` and `FILE-READ-ERROR` instead of throwing `IOException`, `UnauthorizedAccessException`, `PathTooLongException`, `NotSupportedException` or path `ArgumentException`s; failing or `null`-returning adapters are reported as `SCHEMA-VALIDATOR-ERROR`, `RULE-VALIDATOR-ERROR`, `MAPPER-ERROR` and `GEOJSON-EXPORT-ERROR`. Only argument validation still throws (`null` stream, `null`/whitespace path).
